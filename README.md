## 🏢 О компании

**ООО «ФинДрон»** — российский IT-агрегатор, специализирующийся на поставке и интеграции программных решений для беспилотных авиационных систем (БАС).

Мы не создаём дроны и не разрабатываем софт с нуля — мы **подбираем, адаптируем и объединяем** лучшие решения от проверенных вендоров в единую экосистему управления через платформу **ФинДрон HUB**.

## 🏗️ Техническая архитектура

Архитектура платформы спроектирована для пилотного проекта городской экосистемы беспилотного транспорта (ГЭБТ) в Иннополисе.

### Три ключевых блока

```
                    ┌─────────────────────────────────┐
                    │       ФинДрон HUB (ядро)        │
                    │  Агрегационный движок, API-шлюз  │
                    └──────────┬──────────────────────┘
                               │
            ┌──────────────────┼──────────────────┐
            │                  │                  │
   ┌────────▼────────┐ ┌──────▼──────┐ ┌─────────▼────────┐
   │  ЦОД и          │ │ Телеметрия  │ │ Витрина-         │
   │  инфраструктура │ │ и связь     │ │ агрегатор        │
   └─────────────────┘ └─────────────┘ └──────────────────┘
```

### 1. ЦОД — гибридная архитектура (Edge + Атомдата)

**Выбранный сценарий:** Гибрид (Сценарий C) — двухуровневая топология.

| Уровень | Размещение | Назначение | Latency |
|---|---|---|---|
| **Edge-узлы** | Склады, зарядные станции (3 шт.) | Обработка телеметрии real-time, автономные сценарии | <5 мс |
| **Центральный ЦОД** | Атомдата-Иннополис | Агрегация, аналитика, хранение 5 лет, интеграции | 3–8 мс |

**TCO 3 года:** 42–60 млн руб. (vs 79–116 млн для собственного ЦОД).

**Резервирование:** 2 ЦОД (гео-резерв), RPO < 1 мин, SLA 99.9%, автопереключение < 2 сек.

### 2. Телеметрия — многоканальное резервирование

| Канал | Технология | Latency | Дальность | Роль |
|---|---|---|---|---|
| Основной C2 | 5G SA / LTE Cat-M1 | 10–30 мс | Зона покрытия МО | Управление, телеметрия 0.5 сек |
| Резервный C2 | 4G LTE (MVNO) | <50 мс | Региональный | Автопереключение <2 сек |
| IoT / датчики | LoRaWAN (868 МГц) | 0.5–2 сек | до 15 км | Стационарные датчики, ПВЗ |
| Ближняя зона | Wi-Fi 6E / HaLow | 1–5 мс | 50–200 м | Посадочные доки, склады |
| Навигация | GNSS + RTK | <1 мс кор. | Покрытие пилота | Точность <2 см |
| Резерв (аварийный) | Спутник LEO VSAT | 20–80 мс | Глобальный | Потеря всех каналов |

### Потоки данных

```
БАС (борт) → MAVLink/DJI SDK → 5G/4G → Edge-узел → нормализация → ФинДрон HUB
IoT (зарядки, ПВЗ) → LoRaWAN → Edge-узел → ФинДрон HUB
Потребители (приложение) → REST API → ЦОД → ФинДрон HUB
Яндекс Go / городские системы → API-шлюз → ЦОД → ФинДрон HUB
ФинДрон HUB → WebSocket / MQTT → дашборд ситуационного центра (0.5 сек)
```

### 3. Витрина-агрегатор — «Яндекс Go для дронов»

Платформа двусторонней marketplace: клиенты-заказчики (кафе, рестораны, маркетплейсы) ↔ операторы дронов.

| Слой | Назначение |
|---|---|
| **Фронтенд (B2B)** | Клиент создаёт заказ, видит статус, получает аналитику |
| **Агрегационный движок** | Маршрутизация к оптимальному оператору, ETA, ценообразование |
| **Операторский интерфейс** | Управление флотом, задания, телеметрия, биллинг |
| **Потребительский трекер (B2C)** | Дрон на карте, push за 2 мин до прибытия, QR для постамата |

### Интеграции с городскими системами

| Система | Тип | Назначение |
|---|---|---|
| Яндекс Go | REST API (двустороннее) | Статус дорог ↔ воздушное пространство |
| Светофорные контроллеры | OPC-UA / MQTT | Приоритетная фаза при посадке дрона |
| ЕДДС-112 | REST API + WebHook | Карточка инцидента, координация МЧС |
| ФГИС ИВП (Росавиация) | REST API | Автоматическая подача планов полётов |
| ЦОД Атомдата | VPN | Вычисления, хранение, резерв |
| Цифровой двойник Иннополиса | GraphQL / REST | 3D-карта города + позиции дронов RT |

### Информационная безопасность

- **ФЗ-152**: все ПДн хранятся в РФ (Edge + Атомдата)
- **Шифрование**: TLS 1.3 (API), AES-256 (хранение), DTLS (C2 link)
- **IAM**: MFA (TOTP) для операторов, 4 роли (Dispatcher / Operator / Admin / Regulator)
- **SIEM**: интеграция с городским контуром ИБ, хранение событий 1 год
- **Пентесты**: ежеквартально, внешний подрядчик

### План технической реализации

| Этап | Срок | Задачи | CAPEX |
|---|---|---|---|
| 0. Подготовка | Нед. 0–2 | Аудит 5G/4G, обследование площадок, согласование API | — |
| 1. Проектирование | Нед. 2–6 | Архитектура Edge/ЦОД, ТЗ на интеграции, договор Атомдата | 1–2 млн |
| 2. Инфраструктура | Нед. 6–14 | 3 Edge-узла, LoRaWAN, подключение ЦОД, 3 тестовых борта | 6–8 млн |
| 3. Интеграции | Нед. 10–18 | ФГИС ИВП, Яндекс Go, АСУДД, ЕДДС-112 | 3–4 млн |
| 4. Витрина MVP | Нед. 14–22 | Приложение агрегатора, онбординг 3–5 клиентов, постаматы | 2–3 млн |
| 5. Пилот | Нед. 22–30 | 20 дронов, ситуационный центр, первые заказы | ~2 млн OPEX |
| 6. Масштабирование | После 30 | Новые операторы, география, тарифная модель | 10–14 млн/год |

**Итого CAPEX (цифровой контур):** 18–28 млн руб. | **OPEX/год:** 10–14 млн руб.
